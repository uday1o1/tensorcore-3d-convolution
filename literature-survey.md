# Literature and SOTA Survey: Tensor Core Accelerated 3D Convolution for Medical Image Segmentation

Sources below were retrieved and read directly. Verification level, full text or abstract only, is stated per source.

### 0. Fu, Ma, Zhang, Zhao, Lu, Liu. "Enabling Memory-efficient Im2win Convolution with Multi-precision Support on GPU CUDA and Tensor Cores." IJCNN 2026, pp. 1-8, doi:10.1109/IJCNN69854.2026.11729823. [arXiv:2608.20725](https://arxiv.org/abs/2608.20725). Code: [github.com/TensorConv/im2win](https://github.com/TensorConv/im2win)

Read in full text. Primary technique this project examines and extends. Im2win reduces the memory overhead of standard im2col-based convolution by processing input in overlapping windows with contiguous memory access, and this version adds half-precision Tensor Core execution, with zig-zag memory access and asynchronous double-buffered data movement, alongside an improved full-precision CUDA core version of the earlier GPU kernel. Reports up to 2.8 times higher throughput than its own CUDA core implementation, 1.4 times higher than cuDNN, and 6.4 times higher than cuBLAS-based convolution, using on average about 53 percent of cuDNN's memory and 35 percent of cuBLAS-based convolution's. Tested only on standard two-dimensional convolution and only on one GPU, an RTX 3090.

This project reproduced that comparison directly on the same GPU class. On the first RTX 3090 host the kernel result holds on that layer: 37.1 TFLOPS against cuDNN's 23.8 on the authors' conv9 shape in dedicated timing runs, a ratio of 1.56 on that layer, against the 1.4 the paper reports as its overall improvement across twelve layers, though cuDNN's throughput on that shape varies between runs from 17.6 to 42.4 TFLOPS (`results/logs/measurements/`), so the kernel-level ratio depends on which cuDNN run it is set against; on a second RTX 3090 with the same driver and libraries, cuDNN ran at 41.2 to 41.4 TFLOPS in all 25 fresh processes and the released kernel, alternated with it, at 36.3 to 36.9, so there cuDNN is faster at the kernel level (`results/cudnn_conv9_runs_rtx3090.json`, `results/logs/conv9_same_host.log`). However, inspection of the benchmark harness (`tensor_core_tflops/tflops_convs.cpp`) shows the reported metric covers the convolution kernel alone: the `image2window` transform producing the kernel's input is executed on the host before the timing loop and reused across all fifty timed iterations, and allocation and transfer costs accumulate into a separate variable that is written to the log but excluded from the reported TFLOPS. cuDNN's implicit GEMM performs the equivalent rearrangement inside its timed kernel. Implementing that transform on the GPU and measuring it directly moves the end-to-end ratio to 1.13. This accounting difference, rather than the raw kernel speed, is what motivates the dimensional-scaling question this project asks.

### 0b. Lu, Chu, Liu. "Im2win: Memory Efficient Convolution On SIMD Architectures." IEEE HPEC 2022, pp. 1-7, doi:10.1109/HPEC55821.2022.9926408. [arXiv:2306.14320](https://arxiv.org/abs/2306.14320); Lu, Chu, Guo, Liu. "Im2win: An Efficient Convolution Paradigm on GPU." Euro-Par 2023, LNCS, pp. 592-607, doi:10.1007/978-3-031-39698-4_40. [arXiv:2306.14316](https://arxiv.org/abs/2306.14316); Fu, Zhang, Ma, Zhao, Lu, Liu. "High Performance Im2win and Direct Convolutions Using Three Tensor Layouts on SIMD Architectures." IEEE HPEC 2024, pp. 1-7, doi:10.1109/HPEC62836.2024.10938425. [arXiv:2408.00278](https://arxiv.org/abs/2408.00278)

Read in full text. The full lineage of this technique from 2022 to 2024, prior to the 2026 Tensor Core version above. All three, together with source 0, cover only two-dimensional convolution. No transposed, grouped, depthwise, or three-dimensional convolution appears anywhere across four papers spanning 2022 to 2026, which is the specific gap this project addresses. Cited as necessary background, not as recent work.

### 1. Babak and Schaller. "CUDA Kernel Optimization and Counter-Free Performance Analysis for Depthwise Convolution in Cloud Environments." [arXiv:2604.25422](https://arxiv.org/abs/2604.25422), April 2026

Read at abstract level. Confirms depthwise convolution already has dedicated recent CUDA kernel optimization work of its own. This is one input to the decision not to target depthwise layers: depthwise convolution's small per-channel multiplies do not present the large dense matmul shape Tensor Cores accelerate, and layer-wise FLOP analysis confirmed MedNeXt's depthwise spatial convolution carries only 6.2 percent of that model's FLOPs. This project targets dense convolution instead, which is what the windowing scheme assumes; convolution, transposed convolution included, carries 99.6 percent of nnU-Net's FLOPs.

### 2. Roy et al. "MedNeXt: Transformer-Driven Scaling of ConvNets for Medical Image Segmentation." MICCAI 2023, LNCS, pp. 405-415, doi:10.1007/978-3-031-43901-8_39. [arXiv:2303.09975](https://arxiv.org/abs/2303.09975). Code: [github.com/MIC-DKFZ/MedNeXt](https://github.com/MIC-DKFZ/MedNeXt)

Read in full text. Reference baseline, run unmodified. MedNeXt is a ConvNeXt-style architecture built on large-kernel three-dimensional convolutions. Its own text states directly: "The computational requirements of indefinitely scaling kernel sizes in 3D networks quickly becomes prohibitive," which is why the authors introduce compound scaling, balancing kernel size against network width and depth rather than enlarging kernels alone. This confirms, in the paper's own words, that convolution compute cost is an acknowledged constraint in 3D segmentation. MedNeXt is not this project's substitution target, however: its primary spatial convolution is depthwise and layer-wise FLOP analysis measured it at only 6.2 percent of total model FLOPs, too small a share to be informative about a dense-convolution technique.

### 2b. Roy et al. "MedNeXt-v2: Scaling 3D ConvNeXts for Large-Scale Supervised Representation Learning in Medical Image Segmentation." [arXiv:2512.17774](https://arxiv.org/abs/2512.17774), December 2025

Read at abstract level. A recent continuation of the MedNeXt family, confirming the architecture is still actively developed.

### 3. Isensee et al. "nnU-Net: a self-configuring method for deep learning-based biomedical image segmentation." Nature Methods, 2021, 18(2), 203-211, doi:10.1038/s41592-020-01008-z. Earlier preprint read in full text: "nnU-Net: Self-adapting Framework for U-Net-Based Medical Image Segmentation." [arXiv:1809.10486](https://arxiv.org/abs/1809.10486). Code: [github.com/MIC-DKFZ/nnUNet](https://github.com/MIC-DKFZ/nnUNet)

Primary baseline and this project's substitution target. The preprint states directly: "Medical Image Segmentation is currently dominated by deep convolutional neural networks (CNNs)," and describes nnU-Net as "a robust and self-adapting framework on the basis of 2D and 3D vanilla U-Nets," evaluated directly on the Medical Segmentation Decathlon, the same benchmark this project uses. Its plain 3D U-Net uses standard dense `Conv3d` throughout with no depthwise layer anywhere, and direct FLOP analysis (fvcore) put 99.6 percent of its FLOPs in convolution, transposed convolution included, which is why it rather than MedNeXt is the substitution target. Its 2D configuration additionally provides this project's control arm, measured with the shape-generic implementation, since the released conv9 kernel produced no output at the nnU-Net 2D shape checked and none at batch 16, the batch size of every nnU-Net 2D layer (`results/logs/measurements/sweep_nonzero_check.log`, `generality_audit.log`). Still the field's standard reference framework and under active maintenance, though the original paper predates the 2025 to 2026 window this survey covers; it is included as a required, currently-maintained baseline, not as a recent SOTA claim.

### 4. Lu et al. "Johnson-Lindenstrauss Lemma Guided Network for Efficient 3D Medical Segmentation." ICLR 2026. [arXiv:2509.22307](https://arxiv.org/abs/2509.22307)

Read at abstract level. One of the two components of its dual-stream architecture, Johnson-Lindenstrauss lemma-guided convolution, is itself a convolution-level change, so this is not a claim that no other project touches convolution. The distinction is what kind of change: this source changes what the convolution computes, using a dimensionality-reduction technique to reduce the operation itself, while this project changes how an already-defined, unchanged convolution is executed on the GPU. Evidence that efficient 3D medical segmentation is an active area, approached here through the computation being performed rather than its execution.

### 5. Zeng, Zhou, Zhu, Liu. "TokenSeg: Efficient 3D Medical Image Segmentation via Hierarchical Visual Token Compression." [arXiv:2601.04519](https://arxiv.org/abs/2601.04519), January 2026

Read at abstract level. Pursues efficiency through sparse token representation rather than a convolution implementation change. Same pattern as source 4: efficiency addressed at a different level of the system than this project's contribution.

### 6. Rahman and Marculescu. "EffiDec3D: An Optimized Decoder for High-Performance and Efficient 3D Medical Image Segmentation." CVPR 2025, pp. 10435-10444, doi:10.1109/CVPR52734.2025.00976. Code: [github.com/SLDGroup/EffiDec3D](https://github.com/SLDGroup/EffiDec3D)

Read at abstract level. Pursues efficiency through decoder redesign, not the convolution kernel, keeping the differentiation from this project's angle intact. Its code is real, official, and was pushed as recently as December 2025, making it this project's third baseline, a recent, open-source entry alongside nnU-Net and MedNeXt. Its repository license is the UT Austin Research License, which GitHub shows as "Other": it permits academic, research, experimental and personal use, prohibits redistribution, and requires that derivative works be provided to the licensor. Together with sources 4 and 5, this also establishes that efficient 3D medical segmentation is an active 2025-2026 research area, with no surveyed source pursuing the specific angle of a memory-efficient, Tensor-Core-targeting convolution kernel.

### 7. Antonelli et al. "The Medical Segmentation Decathlon." Nature Communications, 2022, 13, 4128, doi:10.1038/s41467-022-30695-9.

Dataset paper. The Medical Segmentation Decathlon is the data source for this project, fully public with no registration requirement.

---

**Summary of the gap.** A memory-efficient, Tensor-Core-targeting convolution technique exists and is actively developed, but has never been extended beyond two-dimensional convolution across four papers from 2022 to 2026: the full text of all four papers (sources 0 and 0b) contains no mention of "3D," "three-dimensional," or "volumetric" anywhere. Three-dimensional medical segmentation efficiency is an active research area, but every recent approach found addresses it at the architecture or representation level, not at the level of the convolution kernel itself.

Direct reproduction of source 0 sharpened this gap into a specific question. The technique's kernel advantage is real but its published comparison excludes the materialization cost that the windowing approach requires and that cuDNN's implicit GEMM avoids by construction; with that cost restored the ratio on the reproduced layer falls to 1.13. What decides the trade is arithmetic intensity, the compute performed per byte of materialized buffer. That framing produces a prediction opposite to the natural intuition: window overlap redundancy does compound per spatial axis, but reduction depth grows alongside it, from `C x 9` to `C x 27` at kernel size 3, so a third dimension amortizes the materialization over three times more compute. Whether windowed convolution therefore does better in 3D than in 2D is unanswered anywhere in the surveyed literature, and it determines whether the paradigm has a future in volumetric workloads. This project sits there: not claiming a speedup, but measuring how the advantage of an entire family of convolution methods scales with dimensionality, inside an architecture (source 3, nnU-Net) whose compute is almost entirely the dense convolution the technique targets.

**Why three-dimensional convolution, not two-dimensional.** Medical imaging volumes such as CT and MRI scans are inherently three-dimensional: a structure like a tumor or a blood vessel has shape and continuity across the depth axis, not just within a single slice. A model built from two-dimensional convolutions applied slice by slice cannot directly capture that cross-slice continuity, which is why nnU-Net's 3D configurations and MedNeXt use true three-dimensional convolutions rather than per-slice processing (nnU-Net's preprint describes it as built "on the basis of 2D and 3D vanilla U-Nets" and evaluates it on volumetric data). This is also precisely why Im2win's exclusively two-dimensional coverage is a real gap and not an academic technicality: the efficiency technique does not yet reach the dimensionality the application domain actually requires.
